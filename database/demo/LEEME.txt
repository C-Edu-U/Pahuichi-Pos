Desde la carpeta del proyecto, con Docker Desktop iniciado:
  powershell -NoProfile -ExecutionPolicy Bypass -File .\bin\Preparar-Demo.ps1

Este es el comando unico de carga, tambien en la PC de Eduardo. Crea el proyecto
Docker pahuichi-demo-hu65: base, fotos y dependencias en volumenes independientes.
No combina archivos Compose ni usa los volumenes de la instancia habitual.
La primera ejecucion descarga/construye las imagenes y requiere internet.

Demo: https://localhost:8446 (HTTP 8086 redirige a HTTPS).
Si el certificado es autofirmado, el navegador pedira aceptar el certificado local.
Si el puerto esta ocupado, definir $env:HU65_HTTPS = '8447' antes del comando.
La instancia habitual conserva su direccion, por ejemplo https://localhost:8443.

FOTOS Y SQL
Las 25 JPG originales se versionan en database/demo/fotos. productos.json indica
que archivo corresponde a cada producto. El cargador usa FotoProducto::comprimir,
igual que el formulario: JPEG cuadrada de 480 px y hasta 200 KB.
La base guarda solo foto-<hash>.jpg. No guarda rutas de Windows. Los archivos se
copian al volumen storage de la demo y se sirven por las rutas existentes.
Al volver a cargar se reponen fotos faltantes; los registros no se vuelven a insertar.

El SQL contiene usuarios ficticios, negocio de ejemplo, productos, promociones,
ventas, detalles, pagos, facturas y sus snapshots, movimientos, arqueos y bitacora.
Las operaciones fueron generadas con los servicios de cobro, promociones, caja,
conteo, arqueo y anulacion del mismo develop, y luego exportadas respetando las
claves foraneas. No se desactivan esas claves ni se importan columnas generadas.
Se ejecuta con bin/demo.php, que aplica las migraciones primero y protege la carga.
No importar manualmente el SQL en la base de uso habitual.
Los precios y datos son de demostracion; ningun documento tiene valor fiscal.

SEGURIDAD Y REPETICION
El cargador solo admite APP_DEMO_HU65=1 y la base pahuichi_demo_hu65. Rechaza una
base poblada sin su marca de carga; nunca elimina ni trunca tablas o registros.
Una marca demo_hu65 se crea solo en la base demo. Guarda la version completada,
no cada ejecucion. Un bloqueo impide dos cargas concurrentes; la transaccion evita
ventas a medias. Una nueva version no reemplaza una demo ya cargada.
No cambia .env, docker-compose.yml, fotos ni datos de la instancia habitual.
Si despues se hacen ventas o cambios en la demo, repetir la carga los conserva.

DETENER SIN BORRAR
Desde el proyecto:
  docker compose -p pahuichi-demo-hu65 -f docker-compose.demo.yml stop
El comando Preparar-Demo.ps1 la vuelve a levantar con los mismos datos.
